# spec-scaffold — greenfield precondition for `/spec-forge` on the Genesis server

**Purpose.** `/spec-forge` builds on an existing crate; the Genesis `server/` starts empty.
This skill lays down the minimal **compiling** greenfield so Phase 3 RED is a healthy
runtime-panic RED (from `unimplemented!()`), not a compile error. It is a **precondition**,
run once before the first `/spec-forge` run — it adds **no phase** and touches the
supervisor/router **not at all** (mirrors `new-model` Phase 2's skip-if-exists scaffold).

## Skip-if-exists guard (run FIRST)

```bash
if [ -f server/Cargo.toml ]; then
  echo "server/ already scaffolded — skipping (nothing to do)"; exit 0
fi
```

Never overwrite an existing `server/Cargo.toml` or any `src/*.rs`. If they exist, stop.

## What it writes (flat layout — ifs Rust convention, never nested `component_manager/…`)

```
server/
├── Cargo.toml           # §2.2 stack: rmcp 2.2.0, rusqlite/sqlite-vec, ort/tokenizers, cucumber; ifs lint gate; NO dangling [[test]] blocks
├── README.md
├── src/
│   ├── lib.rs           # crate root + `serve_stdio()` entry stub
│   ├── main.rs          # thin tokio bin → genesis_memory::serve_stdio()
│   ├── store.rs         # VectorStore::{open,insert,knn} stubs
│   ├── embed.rs         # Embedder::{load,embed} + EMBED_DIM stubs
│   └── consolidate.rs   # ConsolidationConfig + consolidate() stub
└── tests/
    ├── bdd/             # cucumber step defs — empty; /spec-compile fills
    └── golden/          # embedding golden vectors — empty
```

**Rules baked into the scaffold (do not deviate):**
- Every function body is `unimplemented!("Implement via TDD")` — compiles, panics at runtime → RED.
- Stub bodies use **only** std / `anyhow` / `tokio` — **no** external-crate API calls yet.
  The forge-dev-agent introduces `rmcp` / `ort` / `sqlite-vec` wiring during Phase 4 TDD,
  one commit per task, with `cargo test` catching any compile slip immediately.
- **No `[[test]]` blocks** in the initial `Cargo.toml` — each is generated by `/spec-compile`
  (Rust branch) **together with** its `tests/bdd/<slug>_steps.rs`. A `[[test]]` block whose
  `path` does not exist breaks `cargo build`/`cargo test`.
- **No `tests/test_main.rs`** — `main.rs` is thin orchestration; behaviour is covered by lib
  unit tests + cucumber BDD + stdio integration tests (ifs "Notes for the porter" rule).
- The lint gate is verbatim from the ifs reference crates:
  `unsafe_code=forbid`; `unwrap/expect/panic/todo=deny`; `unimplemented=warn` (so stubs compile);
  `pedantic=warn`.

## After scaffolding

1. `P-3` tooling (once per machine): `cargo install cargo-llvm-cov rust-code-analysis-cli`
   (Python 3 already present for the CRAP adapter + hooks).
2. Ensure `server/` is under git (Phase 0a worktree isolation needs a git repo).
3. Run `/spec-forge <feature>` — Phase 0 detects `Cargo.toml` → `state.json.language="rust"`,
   and the Rust branch of every seam (verify/crap/compile) takes over.

The canonical scaffold content is the set of files already written under `server/`; if this
skill and those files ever diverge, the files on disk are the source of truth.

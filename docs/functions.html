What everything does

Every surface Genesis exposes, and what it is for. You will only ever type the first group — the slash commands. Everything below them is machinery those commands drive on your behalf, listed so nothing is a black box.

Slash commands

3

The whole user-facing surface. Typed in Claude Code, from your project folder.

/genesis:new

Start a build. Sensei interviews you, then delegates the authoring to Method. Nothing about Genesis runs until this is invoked — the plugin is dormant otherwise.

optional argument: what the agent should do · commands/new.md
/genesis:promote <name>

Turn an already-built agent into the folder's main Claude. Its persona is merged into CLAUDE.md as a managed block and its enforcement moves to the main thread. The agent stays available as a subagent too.

non-destructive · idempotent · one agent is main at a time · commands/promote.md
/genesis:demote

The exact inverse. Strips the managed block and the main-thread hooks, preserving everything else you had. Takes no argument, because only one agent is ever main.

reports which agent was demoted, or that none was · commands/demote.md

The team that does the building

2

Installed into your project on plugin install. Separate roles, separate tool lists.

sensei

The coordinator, and the only one you talk to. Gathers and verifies every requirement, decides the plan with you, then assembles, wires and installs. It never authors a persona itself and never guesses.

tools: Read Write Edit Bash Glob Grep Agent SendMessage + memory · expertise: agent-building, agentic-teams, expertise-application
method

The test-first craftsman. Writes each agent's acceptance tests before the agent, then the smallest persona that passes them. Has no Agent tool, so it physically cannot delegate — the boundary is config, not a promise.

tools: Read Write Edit Bash Glob Grep SendMessage + memory · expertise: persona-creation, prompt-engineering, expertise-application

Enforcement — the checks that can refuse

5

One native binary, genesis-hook, dispatched by its first argument. A check costs 2–10 ms. Dormant unless a Genesis agent is active.

inject

At session start, hands the agent the house rules and pointers to its expertise store — and, for a session-copied agent, its carried-over digest.

SubagentStart / SessionStart · output capped under the 10,000-char hook limit
gate

Blocks the write itself. A banned phrase, a credential value, or a persona over the 200-line budget is refused at the moment of writing — and the governing rules are re-surfaced right before the attempt.

PreToolUse on Write|Edit
enforce-research

Refuses to assemble a new agent unless the research-expertise step actually ran. Resume-safe: it scans sibling transcripts and writes a durable marker, so a compaction can't make confirmed research invisible.

PreToolUse on Bash · Sensei-scoped · built-in agents exempt
validate

Won't let the agent finish. It must cite the rules it applied — real ids from the manifest, at least three, with evidence that resolves to a file it actually produced or a quote that appears in one. Fabricate any of it and the turn is blocked.

Stop / SubagentStop · fail-closed · prunes build folders, so a 21,000-file tree checks in 0.55 s
session-pointer

Records the live session id so "copy my current session into an agent" knows which session to capture. Fails open and silent — it must never disturb a session.

writes .genesis/current-session.json

Build & install — genesis-cli

10

The one-time build-and-wire layer. Runs at install time, never per tool call. Sensei drives these for you.

assemble

Turns an authored persona + behavior into a real installed agent — as a subagent, or with --main as the folder's own Claude. Registers its required expertise and installs its skills either way.

writes .claude/agents/<name>.md — or CLAUDE.md + .claude/settings.json
bootstrap

Makes a repo a self-contained Genesis workspace: copies the expertise store and hooks into .genesis/, stages the native binaries, registers the memory server, and manages a .gitignore block so the agent's brain and memory travel with the repo.

installs sensei + method wired to the repo-level .genesis
promote

What /genesis:promote runs. Reads the built agent's file, merges its persona into CLAUDE.md, and wires the main-thread hooks.

genesis-cli promote <name> [target_repo] [genesis_home]
demote

What /genesis:demote runs. Removes only Genesis's own managed block and its --main-agent hook entries; your content and your hooks are untouched.

genesis-cli demote [target_repo]
install

Assembles Genesis's own team (Sensei + Method) into a target repo and reports where everything landed.

the plain install path, without a full workspace bootstrap
build-plugin-agents

Regenerates the plugin's own committed agents/*.md from the team sources, so the shipped files can be drift-checked against a fresh render.

maintainer tooling
capture

Session-copy, step 1. Extracts your current session from all six stores and scrubs credentials on the way out.

transcript · auto-memory · context-mode DB · claude-mem · genesis DB · user config → records.jsonl
store

Session-copy, step 2. Turns the captured records into a portable history database plus a deterministic start-of-session digest.

history.sqlite + summary.md
embed

Session-copy, step 3. Spawns the memory server and stores each record under the new agent's id, so the agent can recall its inherited history by meaning.

acts as an MCP stdio client
build-session-agent

Runs all three in order and resolves --session current from the session pointer. This is the "copy my current session into an agent" entry point.

credentials are never copied; pass --known-secret for guaranteed removal

Memory — the MCP tools every agent gets

3

A vector database per agent, on your machine. Scoped by agent id, so an agent only ever sees its own memories.

store

Keep a durable fact or decision. The agent chooses what is worth keeping — this is not a transcript recorder.

embeds the text and writes the row + its vector in one transaction
recall

Find it again later from a loose paraphrase — nearest-neighbour search by meaning, not keyword match. Using a memory makes it stronger.

returns id, text and distance, nearest first · k defaults to 5
consolidate

Fold near-duplicates into the one that earned its place, summing their use counts and keeping a trail of what was replaced.

decay-scored: weight halves every 30 days unless recalled · summarise/evict is deferred to v2

The launcher — bin/genesis-memory.js

6

The one remaining Node file: the irreducible bootstrap, since something has to download the first binary. Node's standard library only.

(no argument)

Downloads and SHA256-verifies the memory server for your platform, caches it per user, and execs it over stdio for Claude Code's MCP channel.

what .mcp.json runs
--run-hook <sub>

Resolves the staged genesis-hook and runs one of its subcommands. Fails open — an unresolvable hook must never block your session.

the plugin's cross-platform hook shim; assembled agents skip it and call the binary directly
--run-cli <sub>

Ensures genesis-cli is present, then runs a subcommand. Fails loud — you asked for it explicitly.

lets a bare plugin install run the orchestrator with no binary on disk yet
--stage-hook <dir>

Copies the hook binary into a repo's .genesis/bin so its enforcement runs a direct native binary.

used by bootstrap
--stage-cli <dir>

The same for the installer binary.

used by bootstrap
--sync <dir>

Refreshes an already-bootstrapped repo's staged binaries to the plugin's version when a stamp shows they are stale. This is how /plugin update actually reaches your repos — no manual staging.

a one-file-read no-op otherwise · run by the plugin's SubagentStart hook

Genesis's own skills

22

Procedures the agents follow. The first two are the build itself; the rest are the spec-driven workflow Genesis used to build its own memory server.

build-agent

The exact procedure Sensei follows to build an agent or team — interview, delegate to Method, assemble, install, verify.

research-expertise

How an agent's expertise is selected and researched — always with you, never chosen silently. Assembly is blocked until it has run.

spec-forge

Supervisor-led multi-agent build: the 9-step flow with worktree isolation, structured plans, TDD discipline, systematic debugging and local code review at every gate.

spec-build

The leaner sibling — the same nine steps and the same gates, orchestrated across five persistent specialist agents.

spec-create · spec-compile

Write a plain-English spec; compile it to Gherkin scenarios plus unit-test stubs.

spec-test · spec-simplify · spec-crap

Run the BDD and unit suites; simplify the implementation; score every function for change risk and fail the build above the threshold.

spec-scaffold · docs-update · app-restart

Lay down a compiling starting point; refresh the architecture docs; stop, start and verify the app.

spec-agent · dev-agent · verify-agent · review-agent · docs-agent

The five specialists spec-build orchestrates — spec, implement, verify, review, document. Silent workers; the supervisor is the only voice.

forge-spec-agent · forge-dev-agent · forge-verify-agent · forge-review-agent · forge-docs-agent

The same five, augmented with discipline skills at defined points — and a code review that runs locally, with no GitHub pull request required.

Vendored discipline skills

brainstorming

Explore intent and requirements before any creative work begins.

writing-plans · executing-plans

Turn a spec into a task-by-task plan; execute one in a separate session with review checkpoints.

test-driven-development

Enforces the Three Laws fresh on each task, rather than trusting a persona to remember them over a long session.

systematic-debugging

When fixes start thrashing, methodology takes over from guessing — root cause first, one hypothesis at a time.

verification-before-completion

Evidence before assertions: run the command and read the output before claiming anything passes.

requesting-code-review · receiving-code-review

Ask for a review; then verify the findings before complying with them, rather than agreeing performatively.

using-git-worktrees

Isolate feature work in its own workspace before a build starts.

subagent-driven-development

Execute independent plan tasks across subagents in the current session.

finishing-a-development-branch

At the end, choose deliberately between merge, pull request and cleanup.
